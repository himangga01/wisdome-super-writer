# Wisdome Super Writer Constitution

## 핵심 원칙

### I. 근거 우선과 완전한 출처 추적 (NON-NEGOTIABLE)

모든 사실 주장, 수치, 일정, 인용, 이미지와 표는 원출처까지 추적 가능해야 한다.
각 수집 항목은 출처 URL, 문서 제목, 발행 주체, 원문 발행 시각, 수집 시각을 MUST
보존한다. 청약 자격·일정·금액과 속보처럼 영향도가 높은 정보는 공신력 있는 1차
출처 한 곳 또는 서로 독립적인 출처 두 곳 이상으로 MUST 검증한다. 사실, 해석, 전망은
본문에서 명확히 구분하고 출처나 인용문을 만들어내서는 안 된다.

근거 없는 자동 생성은 서비스 신뢰와 독자의 의사결정을 동시에 훼손하므로 이 원칙은
다른 모든 편집·발행 목표보다 우선한다.

### II. 합법적 수집과 권리 존중형 멀티모달 처리 (NON-NEGOTIABLE)

수집기는 사이트 이용약관, robots 정책, 저작권, 개인정보, 접근 제어와 호출 제한을
MUST 준수한다. 공식 API, RSS, 공공데이터와 원문 배포 자료를 우선 사용하며 로그인,
유료벽, CAPTCHA 또는 기술적 접근 제한을 우회해서는 안 된다. 원문은 필요한 범위만
인용하고 전문을 재게시하지 않는다.

이미지, PDF, 표, 차트, 동영상, 오디오와 첨부파일은 출처, 권리 상태, 사용 목적을 함께
기록해야 한다. 캡처는 이해에 필요한 최소 영역만 사용하고 출처 링크와 대체 텍스트를
MUST 제공한다. 권리 상태가 불명확한 자료는 내부 분석에만 사용하고 게시물에는 포함하지
않는다.

### III. 주제별 전문 수집 파이프라인

대한민국 부동산 청약정보와 한국·글로벌 반도체 뉴스는 서로 다른 출처 레지스트리,
검색 전략, 신뢰도 기준, 갱신 주기와 정규화 규칙을 가진 독립 주제 어댑터로 MUST
구현한다. 출처 레지스트리는 버전 관리하며 출처 유형, 권위 수준, 접근 방식, 갱신 주기,
허용 콘텐츠 유형과 실패 이력을 포함한다.

수집 결과는 텍스트에 한정하지 않고 표, 구조화 데이터, PDF, 이미지, 차트, 첨부파일과
관련 메타데이터를 공통 증거 모델로 정규화한다. 한 출처나 한 주제의 실패가 다른 작업을
중단시키지 않도록 격리해야 한다.

### IV. 자연스럽고 정직한 편집 품질

게시물은 한국어 우선으로 작성하며 독자가 핵심 사실, 배경, 의미와 주의사항을 빠르게
이해할 수 있는 구조를 MUST 갖춘다. 설치된 `product-marketing`, `content-strategy`,
`copywriting`, `copy-editing`, `image`, `ai-seo` 스킬은 기획과 편집 품질 게이트로
활용하되, 사실 근거나 플랫폼 정책보다 우선할 수 없다.

“AI가 작성한 티가 나지 않게”라는 목표는 반복 표현, 과장, 부자연스러운 문장과 기계적인
구성을 제거하는 편집 품질로 해석한다. 존재하지 않는 취재, 개인 경험, 전문 자격, 인용,
감정 또는 인간 저자를 꾸며내서는 안 되며 법률이나 플랫폼이 요구하는 공개 의무를
회피해서도 안 된다.

### V. 관리자 통제형 안전 발행

서비스는 관리자 전용이며 모든 수집, 변환, 검수, 예약과 발행 작업은 인증된 관리자
권한 아래 수행해야 한다. 외부 플랫폼 자격 증명은 소스와 로그에 노출하지 않고 안전한
비밀 저장소에서 관리한다.

발행 파이프라인은 미리보기, 초안 저장, 승인 모드, 자동발행 모드, 즉시 중지 기능과
감사 로그를 MUST 제공한다. 자동발행은 해당 주제와 채널의 검증 시나리오를 통과하고
관리자가 명시적으로 활성화한 경우에만 허용한다. 동일 콘텐츠 중복 발행과 부분 발행을
방지하는 멱등성 키 및 상태 전이를 MUST 정의한다.

### VI. 테스트 가능성, 관측성, 복구성

출처 파싱, 자료 정규화, 주장-출처 연결, 편집 변환, 플랫폼 발행, 스케줄 실행, 중복 방지,
자격 증명 보호와 실패 복구에는 자동화 테스트가 MUST 존재한다. 외부 플랫폼 연동은
계약 테스트와 통합 테스트를 포함하고, 게시 전후 상태를 검증해야 한다.

각 실행은 상관관계 ID로 수집부터 발행까지 추적 가능해야 하며 단계별 상태, 소요 시간,
수집 건수, 탈락 사유, 검증 결과와 발행 결과를 구조화해 기록한다. 일시적 실패는 제한된
재시도와 백오프를 적용하고, 영구 실패는 격리해 관리자가 원인 확인 후 안전하게 재개할
수 있어야 한다.

## 운영 및 준수 제약

- MVP 주제는 대한민국 부동산 청약정보와 한국·글로벌 반도체 뉴스로 한정한다.
- MVP 발행 채널은 자체 도메인의 관리형 WordPress와 Google Blogger이다. WordPress를
  주 발행·대표 URL 채널로, Google Blogger를 보조 채널로 사용하며 두 채널 모두 공식
  발행 인터페이스와 정책 범위 안에서만 MUST 자동화한다.
- 사용자는 단일 관리자 역할만 지원하며 공개 회원가입과 일반 사용자 기능은 범위에서
  제외한다.
- 모든 일정은 기준 시간대, 중복 실행 정책, 지연 허용 범위와 재실행 규칙을 명시해야
  한다. 기본 운영 시간대는 `Asia/Seoul`이다.
- 원문, 추출 데이터, 생성 초안, 게시 자산과 감사 로그의 보존 기간 및 삭제 정책은
  구현 전에 명세와 계획에 MUST 기록한다.
- 계획 단계의 `research.md`에는 주제별 공식·전문 출처 목록, 수집 방식과 허용 범위,
  콘텐츠 유형 매트릭스, 발행 채널 기능·제약, 실패 모드와 대안을 MUST 포함한다.
- 법적·플랫폼 정책상 허용 여부가 불명확한 수집 또는 게시 방식은 자동화하지 않는다.

## Spec Kit 워크플로 및 품질 게이트

모든 기능은 `$speckit-specify` -> `$speckit-clarify` -> `$speckit-plan` ->
`$speckit-tasks` -> `$speckit-analyze` -> `$speckit-implement` 순서로 진행한다.
구현 후에는 `$speckit-converge`로 명세·계획·작업과 실제 코드의 잔여 차이를 확인한다.

계획과 구현은 다음 게이트를 모두 통과해야 한다.

1. 사용자 스토리와 성공 기준이 독립적으로 검증 가능하다.
2. 주장-출처 추적, 고위험 정보 검증과 인용 범위가 정의되어 있다.
3. 수집 권한, 자산 권리와 플랫폼 정책 준수 방식이 문서화되어 있다.
4. 관리자 인증, 비밀 관리, 승인·자동발행 전환과 즉시 중지가 정의되어 있다.
5. 중복·부분 발행 방지, 재시도, 복구와 감사 로그의 테스트가 작업에 포함되어 있다.
6. 주제별 수집 어댑터와 발행 채널 어댑터가 독립적으로 교체·검증 가능하다.

Constitution 위반은 계획의 `Complexity Tracking`에 근거와 거절한 단순 대안을 기록하지
않는 한 구현을 차단한다. 근거·권리·보안 원칙 위반은 예외 승인이 불가능하다.

## Governance

이 Constitution은 프로젝트의 명세, 계획, 작업 목록과 구현보다 우선한다. 변경은 영향
범위, 마이그레이션 필요성, 관련 템플릿 동기화 결과를 문서화하고 관리자의 승인을 받아야
한다.

버전은 의미적 버전 규칙을 따른다. 원칙 제거 또는 호환되지 않는 재정의는 MAJOR,
원칙이나 필수 게이트 추가는 MINOR, 의미를 바꾸지 않는 설명 보완은 PATCH로 올린다.
모든 `$speckit-plan`과 `$speckit-analyze` 실행은 Constitution 준수 여부를 검토하고,
모든 변경 검토는 출처 추적, 권리 준수, 보안, 테스트와 복구 증거를 확인해야 한다.
