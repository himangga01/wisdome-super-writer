# Feature Specification: 주제 기반 자동 블로그 발행

**Feature Branch**: `main`

**Created**: 2026-07-17

**Status**: Draft

**Input**: User description: "관리자가 부동산 청약 또는 반도체 뉴스 주제를 선택하면
최신 텍스트·시각 자료를 수집하고 출처 기반의 한국어 글로 정제하여 자체 도메인
WordPress와 Google Blogger에 일정에 맞춰 자동 발행하는 서비스"

## Clarifications

### Session 2026-07-17

- Q: 네이버 블로그 자동발행을 어떤 채널로 대체하는가? → A: 자체 도메인의 관리형
  WordPress를 주 발행·대표 원문 채널로 채택하고 Google Blogger를 보조 채널로 유지한다.
- Q: 자동발행 승인 방식은 무엇인가? → A: 관리자 승인을 기본으로 하고 검증 후 자동발행을 활성화한다.
- Q: 주제별 글 생성 단위는 무엇인가? → A: 청약은 공고·정정 건별, 반도체는 일일 요약과 중요 속보를 병행한다.
- Q: 게시 후 원문이 정정·철회되면 어떻게 처리하는가? → A: 양쪽 기존 게시물을 갱신하고 정정 이력을 표시하며, 원문 철회 시 게시 중단 또는 철회 표시한다.
- Q: 반도체 중요 속보는 어떤 기준으로 발행하는가? → A: 정부 규제·수출통제, 공장 중단·공급 차질, M&A·중대 실적, 핵심 기술·양산 발표 중 하나이며 1차 출처 또는 독립 출처 2곳으로 검증된 경우에만 발행한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 출처가 검증된 글 초안 생성 (Priority: P1)

관리자는 대한민국 부동산 청약정보 또는 한국·글로벌 반도체 뉴스를 선택하고 수집을
실행한다. 서비스는 주제별로 승인된 전문 출처를 탐색하고 텍스트, 표, PDF, 이미지,
차트와 첨부파일을 이해 가능한 증거 단위로 수집한 뒤, 출처가 연결된 한국어 글 초안을
생성한다.

**Why this priority**: 신뢰할 수 있는 자료를 읽기 쉬운 글로 만드는 것이 발행과
스케줄링보다 먼저 독립적으로 가치를 제공하는 핵심 기능이다.

**Independent Test**: 두 주제 각각에 대해 수동 실행 한 번으로 출처 목록, 수집 자료,
검증 결과, 한국어 초안과 제외된 자료의 사유를 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 관리자가 부동산 청약정보를 선택한 상태에서, **When** 수집을 실행하면,
   **Then** 청약 일정·자격·금액 등 핵심 사실이 공신력 있는 원출처와 연결된 초안이
   생성된다.
2. **Given** 관리자가 반도체 뉴스를 선택한 상태에서, **When** 수집을 실행하면,
   **Then** 최신성과 신뢰도 기준을 통과한 국내·글로벌 자료가 통합되고 사실과 해석이
   구분된 초안이 생성된다.
3. **Given** 원문에 PDF, 표, 차트 또는 이미지가 있는 경우, **When** 해당 자료가
   게시에 사용할 수 있으면, **Then** 출처·권리 상태·대체 텍스트와 함께 초안에
   포함된다.
4. **Given** 출처나 권리 상태를 검증할 수 없는 자료가 있는 경우, **When** 초안을
   생성하면, **Then** 해당 자료는 게시물에서 제외되고 제외 사유가 기록된다.
5. **Given** 스캔·회전·다단 구성 또는 표가 포함된 여러 페이지 PDF가 있는 경우,
   **When** 내용을 인식하면, **Then** 페이지와 영역 위치, 읽기 순서, 텍스트·표·차트
   구분 및 신뢰도가 보존되고 저신뢰 핵심 값은 자동 게시되지 않는다.

### User Story 2 - 검증된 글을 블로그 채널에 발행 (Priority: P2)

관리자는 생성된 초안과 출처, 시각 자료, 채널별 미리보기를 확인하고 게시 대상으로
전환한다. 서비스는 자체 도메인 WordPress에 전체 원문과 대표 URL을 게시하고,
Google Blogger에는 같은 사실·출처를 유지한 채 채널에 맞춘 글과 WordPress 원문 링크를
게시한다. 두 채널의 제목, 본문, 출처, 이미지 설명과 성공 또는 실패 결과를 각각 관리한다.

**Why this priority**: 초안 생성 이후 실제 운영 시간을 줄이는 두 번째 핵심 가치이며,
수집·편집 기능과 분리해 독립 검증할 수 있다.

**Independent Test**: 검증용 초안 하나를 WordPress와 Google Blogger에 게시하고,
두 게시 URL, 최종 본문의 사실·출처, Blogger의 WordPress 원문 링크, 채널별 상태와
감사 기록이 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 아직 WordPress 대표 URL이 없는 검증 완료 초안이 있을 때, **When** 관리자가
   채널별 미리보기를 열면, **Then** WordPress 전체 원문과 Blogger 맞춤본을 모두 확인할
   수 있고 Blogger 미리보기에는 원문 링크가 발행 시 확정된다는 상태가 표시된다.
2. **Given** 모든 필수 검증을 통과한 초안이 있을 때, **When** 관리자가 승인하거나
   검증 완료된 자동발행 모드가 실행되면, **Then** 두 채널에 각각 한 번만 게시되고
   게시 URL과 시각이 기록된다.
3. **Given** WordPress 발행과 공개 확인은 성공했지만 Blogger 발행이 실패했을 때,
   **When** 관리자가 재시도하면, **Then** WordPress 글을 중복 생성하지 않고 Blogger만
   안전하게 재시도한다.
4. **Given** WordPress 발행 또는 공개 확인이 실패했을 때, **When** 해당 발행 흐름을
   처리하면, **Then** Blogger는 발행하지 않고 WordPress 실패와 보류된 Blogger 상태를
   각각 표시한다.
5. **Given** 관리자가 즉시 중지를 실행했을 때, **When** 대기 중인 게시 작업이 있으면,
   **Then** 새 게시가 시작되지 않고 진행 중·완료·중지 상태가 구분되어 표시된다.
6. **Given** 게시 근거가 된 원문이 정정 또는 철회되었을 때, **When** 변경 내용이
   검증되면, **Then** 두 채널의 기존 게시물이 갱신되고 독자가 볼 수 있는 정정 이력이
   추가된다. 원문 전체가 철회된 경우 채널이 허용하면 게시를 중단하고, 허용하지 않으면
   본문 상단에 철회 상태를 표시한다.
7. **Given** WordPress 원문 게시와 공개 확인이 성공했을 때, **When** Blogger 보조 게시물을
   발행하면, **Then** Blogger 글은 동일한 사실·출처를 유지하면서 WordPress의 대표
   원문 URL을 독자가 확인할 수 있게 제공한다.

### User Story 3 - 일정 기반 반복 실행과 운영 모니터링 (Priority: P3)

관리자는 주제별 실행 일정, 두 발행 채널, 승인 모드와 자동발행 활성 상태를 설정한다.
서비스는 일정에 따라 수집부터 발행까지 반복하고, 각 단계의 결과와 실패 원인을 제공하며
관리자가 안전하게 재실행하거나 일정을 중지할 수 있게 한다.

**Why this priority**: 반복 운영을 자동화하지만 수동 실행과 단건 발행이 검증된 이후에만
안전하게 활성화할 수 있다.

**Independent Test**: 짧은 검증 일정을 등록해 연속 두 번 실행하고, 실행 시각, 중복 방지,
단계별 상태, 실패 재시도와 중지 동작을 확인한다.

**Acceptance Scenarios**:

1. **Given** 활성화된 주제별 일정이 있을 때, **When** 예정 시각이 되면, **Then** 해당
   주제의 수집·검증·초안·발행 흐름이 한 번 시작된다.
2. **Given** 이전 실행이 아직 진행 중일 때, **When** 다음 예정 시각이 도래하면,
   **Then** 설정된 중복 실행 정책에 따라 새 실행이 차단되거나 대기하며 중복 게시하지
   않는다.
3. **Given** 실행이 영구 실패 상태가 되었을 때, **When** 관리자가 상세 내역을 열면,
   **Then** 실패 단계, 원인, 영향받은 채널과 안전한 재개 가능 여부를 확인할 수 있다.

### Edge Cases

- 전문 출처가 일시적으로 응답하지 않거나 자료 구조를 변경한 경우
- 동일 사건을 여러 출처가 서로 다른 제목과 시각으로 보도한 경우
- 반도체 사건이 중요 속보 범주에는 해당하지만 검증 출처 수를 충족하지 못한 경우
- 청약 일정이나 정정 공고가 기존 게시 내용과 충돌해 양쪽 게시물을 수정해야 하는 경우
- 속보가 후속 발표에서 정정·철회되어 기존 게시물을 수정하거나 철회 표시해야 하는 경우
- PDF가 스캔 이미지, 회전·왜곡된 페이지, 다단 구성 또는 혼합 언어를 포함하는 경우
- PDF가 암호화·손상됐거나 안전 한도를 초과해 내용을 신뢰성 있게 추출할 수 없는 경우
- 이미지·차트는 이해에 중요하지만 게시 권리를 확인할 수 없는 경우
- 생성된 글의 주장과 연결된 출처가 발행 직전에 사라지거나 변경된 경우
- 채널별 글자 수, 이미지 수, 제목 또는 태그 제한을 초과한 경우
- 한 채널만 성공한 뒤 재시도 또는 전체 작업 재실행이 발생한 경우
- 관리자 자격 증명이 만료되거나 권한이 철회된 경우
- 예약 실행 중 관리자가 즉시 중지하거나 일정을 수정한 경우
- 수집 결과가 없거나 신뢰도 기준을 통과한 자료가 부족한 경우

### Evidence, Rights & Publication Coverage *(mandatory for collection/publishing features)*

- 청약 자격·일정·금액과 정정 정보는 공신력 있는 1차 출처로 검증한다.
- 반도체 속보의 핵심 사실은 1차 발표 자료 또는 독립적인 두 출처 이상으로 검증한다.
- 각 주장과 자료에는 원문 URL, 제목, 발행 주체, 원문 발행 시각과 수집 시각을 연결한다.
- 원문 인용은 이해에 필요한 최소 범위로 제한하고 원문 전체를 재게시하지 않는다.
- 이미지, 캡처, 표와 첨부파일은 권리 상태가 확인된 경우에만 출처와 대체 텍스트를
  포함해 게시한다.
- 로그인, 유료벽, CAPTCHA 또는 기술적 접근 제한을 우회하는 수집은 범위에서 제외한다.
- 미리보기, 발행 조건, 채널별 상태, 중복 방지, 중지, 재시도와 수동 복구 결과를 보존한다.

## Scope Boundaries

### In Scope

- 대한민국 부동산 청약정보 주제 어댑터
- 한국·글로벌 반도체 뉴스 주제 어댑터
- 승인된 출처 레지스트리와 주제별 검색·검증 기준
- 텍스트, 표, PDF, 이미지, 차트와 첨부파일의 내용 이해 및 출처 관리
- 한국어 우선의 출처 기반 글 초안과 시각 자료 구성
- 자체 도메인 WordPress 및 Google Blogger 발행 흐름
- 관리자 전용 수동 실행, 일정 실행, 중지, 재시도와 감사 내역

### Out of Scope

- 일반 사용자 회원가입, 다중 조직 또는 공개 콘텐츠 작성 기능
- 두 MVP 주제 외 임의 주제의 자동 온보딩
- 유료벽, 로그인, CAPTCHA 또는 접근 제한 우회
- 권리 상태가 불명확한 원문·이미지·첨부파일의 재게시
- 실제 경험, 취재, 자격, 인용 또는 인간 저자를 허위로 표현하는 글
- 투자, 청약 당첨 또는 법률 결과를 보장하는 조언
- 네이버 블로그를 포함해 공식 쓰기 인터페이스가 없는 채널의 UI 클릭, 세션 재사용 또는
  비공식 내부 인터페이스를 이용한 자동 게시

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 서비스는 인증된 관리자만 모든 기능에 접근할 수 있게 해야 한다.
- **FR-002**: 관리자는 부동산 청약정보와 반도체 뉴스 중 실행할 주제를 선택할 수 있어야 한다.
- **FR-003**: 서비스는 주제별 출처 레지스트리와 출처 신뢰도·갱신 주기·허용 자료 유형을
  관리해야 한다.
- **FR-004**: 서비스는 주제에 따라 서로 다른 검색, 최신성 판단, 검증과 제외 규칙을
  적용해야 한다.
- **FR-005**: 서비스는 텍스트, 구조화 데이터, PDF, 표, 이미지, 차트와 첨부파일을
  수집 대상으로 처리해야 한다.
- **FR-006**: 서비스는 수집 자료의 내용, 메타데이터, 원출처와 권리 상태를 하나의
  증거 항목으로 연결해야 한다.
- **FR-007**: 서비스는 서로 중복되거나 충돌하는 자료를 식별하고 선택·병합·제외 결과를
  기록해야 한다.
- **FR-008**: 서비스는 검증을 통과한 증거만 사용해 한국어 우선 글 초안을 생성해야 한다.
- **FR-009**: 초안은 제목, 요약, 본문 구조, 핵심 사실, 배경, 해석·전망 구분, 출처와
  필요한 시각 자료 설명을 포함해야 한다.
- **FR-010**: 서비스는 청약정보를 신규 공고·정정 공고별 글로 생성하고, 반도체 뉴스는
  일일 요약글과 중요 속보글을 병행해야 한다.
- **FR-011**: 관리자는 최종 게시 전 초안, 주장별 출처, 사용·제외된 자료와 채널별
  미리보기를 확인할 수 있어야 한다. WordPress 대표 URL이 아직 없을 때 Blogger
  미리보기는 최종 발행 시 원문 링크가 결합될 위치와 미확정 상태를 명확히 표시해야 한다.
- **FR-012**: 서비스는 MVP에서 자체 도메인 WordPress와 Google Blogger 두 채널을 모두
  지원하고, WordPress를 주 발행·대표 원문 채널로 지정하며 동일 초안의 채널별 발행
  상태와 게시 URL을 각각 관리해야 한다.
- **FR-013**: 서비스는 관리자 최종 승인을 기본 발행 조건으로 적용하고, 주제·채널별
  검증 시나리오를 통과한 뒤 관리자가 명시적으로 활성화한 경우에만 자동발행해야 한다.
- **FR-014**: 관리자는 주제별 실행 일정, 활성 상태, 대상 채널과 중복 실행 정책을
  설정할 수 있어야 한다.
- **FR-015**: 서비스는 동일 실행 또는 동일 콘텐츠가 채널에 두 번 게시되지 않도록 해야 한다.
- **FR-016**: 서비스는 한 채널의 실패가 다른 채널의 성공 결과를 되돌리거나 중복
  생성하지 않도록 채널별 상태를 관리해야 한다.
- **FR-017**: 관리자는 전체 자동화를 즉시 중지하고 안전한 작업만 선택적으로 재개할 수
  있어야 한다.
- **FR-018**: 서비스는 실행별 수집, 검증, 초안, 발행과 복구 상태를 일관된 식별자로
  추적해야 한다.
- **FR-019**: 관리자는 실패 단계, 원인, 영향 범위, 재시도 횟수와 최종 결과를 확인할 수
  있어야 한다.
- **FR-020**: 서비스는 원문 증거와 초안을 90일, 발행 기록과 감사 내역을 1년 보존하고
  관리자가 정책에 따라 삭제할 수 있게 해야 한다.
- **FR-021**: 서비스는 게시 근거의 정정·철회를 감지하고 검증한 뒤 WordPress와
  Google Blogger의 기존 게시물을 동일한 최신 사실로 갱신하며 정정 이력을 표시해야 한다.
  원문 전체가 철회된 경우 채널이 허용하면 게시를 중단하고, 그렇지 않으면 본문 상단에
  철회 상태를 표시하며 모든 변경을 감사 내역에 기록해야 한다.
- **FR-022**: 서비스는 반도체 사건이 정부 규제·수출통제, 공장 중단·공급 차질,
  M&A·중대 실적, 핵심 기술·양산 발표 중 하나에 해당하고 1차 출처 또는 독립 출처
  두 곳 이상으로 검증된 경우에만 중요 속보글을 생성해야 한다. 조건을 충족하지 못한
  자료는 속보로 발행하지 않고 일일 요약 후보로 보류해야 한다.
- **FR-023**: 서비스는 Blogger 게시물을 채널에 맞게 구성하되 WordPress 원문의 사실과
  출처 의미를 유지하고, 해당 WordPress 대표 URL을 독자가 확인할 수 있게 표시해야 한다.
- **FR-024**: 서비스는 텍스트형·스캔형 PDF의 각 페이지에서 텍스트, 읽기 순서, 표,
  차트와 주요 시각 영역을 구분하고 페이지·영역 위치와 인식 신뢰도를 보존해야 한다.
  청약 가격·날짜·자격과 같은 핵심 값이 저신뢰이거나 서로 충돌하면 자동 게시를 차단하고
  관리자 검토를 요구해야 한다.

### Compliance and Editorial Requirements *(mandatory when applicable)*

- **CR-001**: 모든 게시된 사실 주장에는 독자가 도달할 수 있는 원출처가 연결되어야 한다.
- **CR-002**: 권리 상태를 확인할 수 없는 비텍스트 자료는 게시물에서 제외되어야 한다.
- **CR-003**: 게시물은 반복·과장·기계적 문장을 제거하되 존재하지 않는 경험, 취재,
  자격, 감정, 인용 또는 인간 저자를 만들어내서는 안 된다.
- **CR-004**: 외부 채널 자격 증명은 관리자 권한 아래 보호되고 화면·로그·게시물에
  노출되어서는 안 된다.
- **CR-005**: 모든 수집과 발행 방식은 해당 출처와 채널의 이용 조건 및 접근 제한을
  준수해야 한다.
- **CR-006**: 이미지, 캡처와 차트에는 출처, 대체 텍스트와 사용 근거가 기록되어야 한다.
- **CR-007**: 초안 품질 평가는 사실 정확성, 출처 완전성, 한국어 가독성, 중복 표현,
  과장과 구조적 명확성을 포함해야 한다.

### Key Entities

- **Admin**: 주제, 출처, 일정, 발행 상태와 자격 증명을 관리하는 유일한 사용자 역할.
- **Topic**: 부동산 청약정보 또는 반도체 뉴스와 그 수집·검증·편집 정책 및 중요 속보
  분류 기준.
- **Source Definition**: 출처 주소, 발행 주체, 유형, 신뢰 수준, 접근 조건, 갱신 주기와
  허용 자료 유형.
- **Collection Run**: 특정 주제와 시간 범위에 대한 한 번의 수집·검증·작성 실행.
- **Source Item**: 수집한 원문 또는 발표 자료와 발행·수집 메타데이터.
- **Evidence Asset**: 텍스트, 표, PDF, 이미지, 차트 또는 첨부파일에서 얻은 근거, 페이지·
  영역 위치, 인식 신뢰도와 권리 상태.
- **Claim**: 초안의 사실 주장과 이를 뒷받침하는 하나 이상의 증거 연결.
- **Draft Article**: 제목, 요약, 본문, 출처, 시각 자료, 품질 검증, 개정 번호,
  정정 이력과 철회 상태를 가진 게시 후보.
- **Publication Target**: 채널, 대상 블로그, 주 발행·보조 역할과 발행 가능 상태.
- **Publication Job**: 초안과 채널을 연결한 생성·수정·철회 시도, 중복 방지 키, 결과와
  게시 URL.
- **Schedule**: 주제별 실행 규칙, 시간대, 활성 상태와 중복 실행 정책.
- **Audit Event**: 관리자 또는 자동 작업이 만든 상태 변경과 원인·결과 기록.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 검증 가능한 자료가 존재하는 정상 실행의 90% 이상이 시작 후 30분 이내에
  출처가 연결된 초안을 생성한다.
- **SC-002**: 게시된 사실 주장의 100%가 하나 이상의 허용된 원출처 또는 교차 검증
  증거에 연결된다.
- **SC-003**: 게시된 이미지, 캡처, 표와 첨부자료의 100%가 출처, 권리 상태와 대체
  텍스트를 가진다.
- **SC-004**: 주제별 검증 표본 20건에서 핵심 사실의 95% 이상이 원출처와 일치하고,
  근거 없는 사실 또는 허위 인용은 0건이어야 한다.
- **SC-005**: 동일 작업을 100회 재시도하는 검증에서 동일 채널에 발생하는 중복 게시가
  0건이어야 한다.
- **SC-006**: 활성 일정의 95% 이상이 예정 시각 전후 5분 이내에 실행을 시작하거나,
  지연·차단 사유를 관리자에게 표시한다.
- **SC-007**: 관리자는 실패한 실행에서 2분 이내에 실패 단계, 원인, 영향받은 채널과
  재개 가능 여부를 찾을 수 있다.
- **SC-008**: 관리자 평가에서 초안의 80% 이상이 사실 수정 없이 구조·문장 수준의 경미한
  편집만으로 게시 가능한 판정을 받는다.
- **SC-009**: 검증된 정정·철회의 95% 이상이 감지 후 30분 이내에 두 채널의 기존
  게시물과 정정 이력에 반영된다.
- **SC-010**: 중요 속보 분류 검증 표본에서 기준 범주와 출처 검증 조건을 충족하지 않은
  반도체 자료가 속보로 게시되는 비율은 0%여야 한다.
- **SC-011**: 게시에 성공한 Blogger 글의 100%가 대응하는 WordPress 대표 원문 URL을
  제공하고, 표본 검수에서 두 채널의 사실·출처 의미 불일치가 0건이어야 한다.
- **SC-012**: 텍스트형·스캔형·회전형·표 포함 PDF로 구성된 골든 표본 30페이지에서 핵심
  날짜·금액·자격·고유명사의 95% 이상이 원문과 일치하고, 페이지·영역 위치가 없는 인식
  결과와 저신뢰 핵심 값의 자동 게시가 각각 0건이어야 한다.

## Assumptions

- 서비스의 작업명은 저장소명을 따라 `Wisdome Super Writer`로 사용한다.
- 모든 게시물의 기본 언어는 한국어이며, 해외 반도체 원문도 한국어로 요약·설명한다.
- 기본 운영 시간대는 `Asia/Seoul`이다.
- 초기 출처 레지스트리는 계획 단계에서 공식·전문 출처를 조사해 관리자가 승인한다.
- 공개적으로 접근 가능하고 자동 수집과 활용이 허용된 자료만 운영 대상에 포함한다.
- 관리자에게 자체 도메인 WordPress와 Google Blogger의 적법한 소유·관리 권한이 있다고
  가정한다.
- 게시물은 정보 제공 목적이며 투자, 청약 당첨, 법률 또는 재무 결과를 보장하지 않는다.
- 외부 출처나 발행 채널의 정책·기능 변경은 정상적인 운영 실패로 취급하고 관리자에게
  조치 가능한 상태로 표시한다.

## Dependencies

- 각 주제에 대해 신뢰할 수 있고 지속적으로 접근 가능한 원출처가 존재해야 한다.
- 자체 도메인 WordPress와 Google Blogger가 자동 게시와 필요한 콘텐츠 형식을 허용하고,
  관리자가 각 채널의 공식 연결 권한을 제공해야 한다.
- 텍스트 외 자료의 게시에는 출처별 사용 권리 또는 명시적 허용 근거가 필요하다.
- 최신성, 권리, 발행 정책은 계획 단계의 조사 결과에 따라 명세 범위가 축소될 수 있다.
